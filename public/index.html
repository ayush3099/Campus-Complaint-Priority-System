Priority Algorithm & Architecture

Mathematical scoring model, Java OOP design, and Data Structures used in this project.

1. Dynamic Impact Formula

Instead of First-Come-First-Serve (which causes urgent hazards to be ignored), CampusCare uses a multi-factor priority algorithm:

$$\text{Priority Score} = U + C_{\text{cluster}} + E_{\text{upvotes}} + A_{\text{aging}} + W_{\text{category}}$$
ComponentWeight / PointsExplanation
Urgency ($U$) Low = 5, Med = 12, High = 22, Emergency = 32 Base severity determined by student at submission time.
Cluster Multiplier ($C$) $+4$ pts per similar open complaint Detects widespread outages across the same block or category.
Student Endorsements ($E$) $+3$ pts per "Me Too!" upvote Democratic validation: multiple students corroborating the problem.
Anti-Starvation Aging ($A$) $+2$ pts per day pending Prevents low-priority tickets from being neglected indefinitely.
Category Factor ($W$) Electricity/Security = $+3$, Water/AV = $+2$, IT = $+1$ Safety and essential campus utilities receive an baseline boost.

2. Priority Bands & Service Level Agreements (SLA)

Critical (≥ 35 pts)

Immediate dispatch. Safety hazard or campus-wide blackout.

SLA: Under 4 Hours

High (25 – 34 pts)

Major lecture disruption or heavy water leak.

SLA: Under 24 Hours

Medium (15 – 24 pts)

Moderate classroom inconvenience.

SLA: Under 3 Days

Low (< 15 pts)

Cosmetic repairs or non-disruptive feedback.

SLA: Under 7 Days

3. Java 21 Technical Implementation

  • JDK HTTP Server: Zero external frameworks (pure Java `com.sun.net.httpserver.HttpServer`).
  • Thread-Safe Concurrency: `Executors.newFixedThreadPool(10)` handles simultaneous student and admin requests.
  • Data Persistence: Atomic file storage (`data/complaints.tsv`) with auto-recovery and UTF-8 handling.
  • Heap/Priority Queue Sorting: Comparator-based dynamic sorting by priority score descending and timestamp ascending.
